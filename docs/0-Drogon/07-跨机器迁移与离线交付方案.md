# 07 - 跨机器迁移与离线交付方案

> 目标：把当前欧拉虚拟机（`192.168.80.136`）中 IBMCP 使用到的**全部库、软件、工具、配置与数据**，稳定、快速地移植到任意同架构的物理机或虚拟机，包括**离线/隔离环境**。
>
> 数据来源：对源机器的一次完整资产盘点（见 `附录 A`），本文所有版本号、路径、大小均为实测值，非臆测。

---

## 1. 迁移范围（到底要搬什么）

把"欧拉机器上 IBMCP 用到的一切"分成 **6 层**，迁移时按需组合：

| 层 | 内容 | 当前位置 / 大小 | 搬迁方式 |
|---|---|---|---|
| **L1 系统底座** | openEuler OS + 内核 | 24.03 LTS-SP3 / 6.6.0-132 / x86_64 | 目标机预装同版本 ISO |
| **L2 系统包** | gcc/cmake/openssl/libpq/mosquitto/nginx/docker-ce 等（含运行时传递依赖） | dnf 安装，见 §附录 A | 在线 `dnf install` 或 离线 rpm 仓库 |
| **L3 自研/第三方构建产物** | drogon(静态) + trantor(静态) + libmodbus(.so) + open62541(.so) + env.sh | `/home/meng/ibmbuild`，**19 MB** | 直接打包目录（已编译，无需重编） |
| **L4 Docker 镜像** | postgres:15 / redis:7 / nodered/node-red:latest | 共 ~450 MB（压缩） | `docker save` 离线镜像包 |
| **L5 配置与系统集成** | nginx.conf / systemd unit / ld.so.conf / sysctl / profile.d / SELinux&firewall | `/etc/` 下若干文件 | 脚本幂等写入 |
| **L6 应用与数据** | dist(二进制+迁移)、frontend-dist、项目源码；PG/Redis/Node-RED 数据卷 | dist ~5MB；数据卷可选 | bundle 还原 + 可选数据迁移 |

### 关键事实（来自盘点）

- 后端二进制 `ibmcp_server` 4.9 MB，`ldd` **零 not found**；其运行时动态库**全部来自系统层**（openssl / libpq / libargon2 / jsoncpp / yaml-cpp / c-ares / libuuid / mosquitto 及其传递依赖 krb5 / openldap / sasl / selinux / pcre2 / crypt）。
- drogon / trantor 是**静态库**，已链接进二进制，运行时不依赖其 .so（但**编译时**需要头文件 + cmake config）。
- libmodbus / open62541 是 `.so`，通过 `/etc/ld.so.conf.d/ibmcp-build.conf` 注册到 ldconfig。
- docker 共 3 个镜像、3 个命名卷（`ibmcp_pg_data` / `ibmcp_redis_data` / `ibmcp_nodered_data`），3 容器均 healthy。

## 2. 兼容性约束（目标机硬性要求）

为保证"搬过去直接跑"，目标机必须满足：

1. **OS**：`openEuler 24.03 LTS-SP3`，架构 `x86_64`。
   - 原因：二进制在 glibc 2.38 下编译；跨大版本（如 22.03 → glibc 2.34）可能 ABI 不兼容，需**重新编译**而非直接搬二进制。
2. **内核**：≥ 5.x（SP3 自带 6.6，满足）。
3. **磁盘**：≥ 5 GB 可用（L2 包 ~500MB + L3 19MB + L4 镜像 ~450MB + L6 数据）。
4. **内存**：≥ 2 GB（运行容器 + 服务）。
5. （生产环境）建议关闭 SELinux / firewalld 或放行 80/5432/6379/1880/8000 端口。

> 若目标机是其他 OS（CentOS/RHEL/UOS/Kylin），**不要直接搬二进制**：走"在线路径"在目标机上重新 `bootstrap.sh` + `build.sh` 编译；离线包的 rpm 也需换源重做。

## 3. 总体策略：两条路径

```
                    ┌──────────────────────────────────┐
                    │  源机器（当前欧拉，已构建成功）   │
                    │  bash make-offline.sh → 3 个包   │
                    └───────────────┬──────────────────┘
                                    │ U盘 / scp / 内网传输
            ┌───────────────────────┼────────────────────────┐
            ▼                       ▼                        ▼
   ┌─────────────────┐    ┌─────────────────────┐   ┌──────────────────┐
   │ 路径 A：目标机有网 │    │ 路径 B：目标机离线/隔离 │   │ 数据迁移（可选） │
   │ sudo bootstrap.sh│    │ sudo restore.sh --all│   │ pg_dump / 卷拷贝 │
   │ bash build.sh    │    │   （分钟级，零联网）  │   │                  │
   │ sudo deploy.sh   │    │                     │   │                  │
   └─────────────────┘    └─────────────────────┘   └──────────────────┘
```

- **路径 A（在线）**：目标机能联网。最简单，直接复用现有 `bootstrap.sh` → `build.sh` → `deploy.sh`。耗时长（drogon 编译 5–10 分钟），依赖外网/镜像源可达。适合开发联调环境。
- **路径 B（离线）**：目标机不能联网或要**稳定、快速、可复现**交付。用源机器预生成的离线包一键还原。**这是本方案的重点**。

## 4. 离线交付包设计（三张盘 + 一把锁）

在源机器（当前欧拉）上运行 `make-offline.sh`，生成以下 4 个文件，拷到 U 盘或内网：

```
ibmbuild-offline-<日期>-<gitsha>/
├── ibmbuild-rpms.tar.gz      # L2：离线 rpm 本地仓库（~400 MB，含 docker-ce）
├── ibmbuild-base.tar.gz      # L3+L5：ibmbuild 树 + 系统配置快照（~25 MB）
├── ibmbuild-app.tar.gz       # L4+L6：dist + frontend-dist + docker 镜像 + 源码部署脚本（~500 MB）
└── versions.lock             # 版本锁 + sha256 校验清单（稳定性的核心）
```

### 4.1 `versions.lock` —— 稳定性的核心

记录所有可版本化资产的精确指纹，还原时逐一校验，避免"装到的版本不一样"：

```
# 由 make-offline.sh 生成，请勿手改
os=openEuler 24.03 LTS-SP3
arch=x86_64
kernel=6.6.0-132.0.0.111.oe2403sp3.x86_64
glibc=2.38-84

# 关键系统包（精确版本）
gcc=12.3.1-111.oe2403sp3
cmake=3.27.9-8.oe2403sp3
libpq=15.20-1.oe2403sp3
openssl=3.0.12-55.oe2403sp3
jsoncpp=1.9.5-5.oe2403sp3
yaml-cpp=0.7.0-2.oe2403sp3
mosquitto=2.0.20-2.oe2403sp3
nginx=1.24.0-16.oe2403sp3
docker-ce=29.10.0-1.el9
...
# 自研/第三方
drogon=v1.9.5 (static)
trantor=<submodule pinned>
libmodbus=<version>
open62541=1.4
# docker 镜像（digest 而非 tag，确保字节一致）
postgres:15=sha256:10f9e886f772...
redis:7=sha256:2e3eb11462c4...
nodered/node-red:latest=sha256:3622786c15b6...
# 各 tarball 的 sha256
ibmbuild-rpms.tar.gz=<sha256>
...
```

`restore.sh` 还原后会：核对目标机 OS 版本 → 校验每个 tarball 的 sha256 → 核对 docker 镜像 digest → 任一不符则告警/中止。

## 5. 详细操作流程

### 5.1 源机器：制作离线包（一次性，或每次发版）

在当前欧拉（已成功构建的机器）上：

```bash
cd /home/meng/ibmcp
bash deployments/openeuler/make-offline.sh
# 产物 → /home/meng/ibmbuild-offline-<日期>/  （或 BUNDLE_OUT 指定）
```

该脚本内部做的事（设计，见 §7）：
1. 收集 ibmbuild 树 → `ibmbuild-base.tar.gz`
2. 收集系统配置文件快照 → 也打进 base 包
3. `dnf download --resolve` 拉取所有 IBMCP 相关 rpm + 依赖 → `createrepo` → `ibmbuild-rpms.tar.gz`
4. 收集 dist / frontend-dist / 部署脚本 → `docker save` 三个镜像 → `ibmbuild-app.tar.gz`
5. 生成 `versions.lock` 与每个 tarball 的 sha256

> 注意：rpm 包从**当前机器已启用的仓库**下载（OS / EPOL / everything / update / docker-ce-stable）。源机器必须能联网跑这一步。若源机器也离线，需先在一台有网的同版本机器上下载好 rpm 仓库。

### 5.2 目标机器：一键还原（离线）

把整个 `ibmbuild-offline-<日期>/` 目录拷到目标机（U盘挂载 `/mnt/usb` 或 scp），然后：

```bash
sudo bash /mnt/usb/ibmbuild-offline-*/restore.sh --all /mnt/usb/ibmbuild-offline-*/
```

`restore.sh --all` 按顺序执行（每步幂等，已完成的自动跳过）：

| 步骤 | 动作 | 对应层 |
|---|---|---|
| 1 校验 | 读 `versions.lock`，核对 OS 版本 + 各包 sha256 | — |
| 2 装系统包 | 解压 rpm 仓库到 `/opt/ibmbuild-repo`，写 `.repo`，`dnf install` 所有 L2 包 | L2 |
| 3 还原 ibmbuild | 解压到 `/home/<user>/ibmbuild`（路径可配），生成/覆盖 `env.sh` | L3 |
| 4 注册运行时库 | 写 `/etc/ld.so.conf.d/ibmcp-build.conf` → `ldconfig` | L5 |
| 5 系统配置 | nginx.conf、systemd unit、sysctl(ptrace)、profile.d；关闭 SELinux/firewalld（可选） | L5 |
| 6 Docker | 启动 docker，`docker load` 三个镜像，`docker compose up -d`（PG+Redis+NodeRED） | L4 |
| 7 应用 | 还原 dist + frontend-dist，跑 SQL 迁移，`systemctl enable --now ibmcp-api` | L6 |
| 8 健康检查 | `curl /api/v1/ping`、`nginx -t`、容器 healthy 检查 | — |

完成后输出访问地址，与现有 `deploy.sh` 一致。

**也支持只还原部分**：`restore.sh --rpms`、`--base`、`--app`、`--data` 可单独跑，便于增量更新。

### 5.3 数据迁移（可选，生产环境）

L6 的数据卷是否迁移取决于场景：

- **全新环境**：不迁数据，`deploy.sh` 会自动跑 SQL 迁移建空表 → 业务从零开始。
- **要搬历史数据**：
  - **PostgreSQL**（推荐逻辑导出，跨机器最稳）：
    ```bash
    # 源
    docker exec ibmcp-postgres pg_dump -U ibmcp -d ibmcp -Fc -f /tmp/ibmcp.dump
    docker cp ibmcp-postgres:/tmp/ibmcp.dump ./ibmcp.dump
    # 目标（容器已起、空库）
    docker cp ./ibmcp.dump ibmcp-postgres:/tmp/
    docker exec ibmcp-postgres pg_restore -U ibmcp -d ibmcp --clean --if-exists /tmp/ibmcp.dump
    ```
  - **整卷迁移**（要求两端 pg 大版本完全一致，同为 15）：直接 `docker run --rm -v ibmcp_pg_data:/data -v $PWD:/backup alpine tar czf /backup/pg_data.tgz -C /data .`，目标机反向解压到同名卷。**比逻辑导出脆弱，仅在版本严格一致时用**。
  - **Redis**：通常不迁（缓存）；如需，拷贝 `dump.rdb`。
  - **Node-RED**：迁 `ibmcp_nodered_data` 卷（含 flows_cred.json，注意密钥）。

## 6. 版本锁定与校验（稳定性保障）

"稳定快速移植"的最大敌人是**版本漂移**。三道防线：

1. **OS 锁定**：`versions.lock` 声明目标 OS；`restore.sh` 第一步校验，不符则拒绝（或降级为警告）。
2. **rpm 锁定**：离线仓库里是**精确版本**的 .rpm（`dnf download --resolve` 下载的就是当前装的版本），目标机 `dnf install` 不会拉到更新的版本，因为本地仓库只有这一份。
3. **镜像锁定**：用 `docker image inspect --format '{{index .RepoDigests 0}}'` 存 digest，还原后 `docker load` 出来对比，确保镜像字节一致（tag 可被覆盖，digest 不会）。
4. **二进制校验**：`ibmcp_server` 的 sha256 记录在锁文件，还原后比对。

## 7. 待实现脚本设计

当前仓库已有 `make-bundle.sh`（只打 L3+L6 部分）和 `bootstrap.sh`/`deploy.sh`（在线路径）。**离线路径**需新增两个脚本：

### 7.1 `deployments/openeuler/make-offline.sh`（源端，有网）

输入：当前机器已成功构建。
输出：`$OUT/ibmbuild-offline-<ts>/` 目录含 4 个文件。
关键命令：
```bash
# rpm 离线仓库（含 docker-ce，从已启用仓库下载精确版本 + 依赖）
mkdir -p $stage/rpms
dnf download --resolve --alldeps --destdir $stage/rpms \
  gcc gcc-c++ cmake make gdb \
  libpq-devel libargon2-devel openssl-devel zlib-devel \
  jsoncpp-devel yaml-cpp-devel c-ares-devel util-linux-devel \
  mosquitto-devel nginx \
  docker-ce docker-ce-cli containerd.io docker-compose-plugin \
  git wget curl tar unzip autoconf automake libtool
createrepo_c $stage/rpms   # 或 createrepo
tar czf ibmbuild-rpms.tar.gz -C $stage rpms
```
> 传递依赖（krb5/openldap/sasl 等）由 `--resolve --alldeps` 自动拉入。

### 7.2 `deployments/openeuler/restore.sh`（目标端，离线，幂等）

输入：离线包目录。
核心逻辑：每步先检测"是否已就绪"，已就绪则跳过（幂等）。
```
已装 gcc?       → 跳过 rpm
ibmbuild 存在?  → 跳过 base 解压
ld.conf 存在?   → 跳过 ldconfig 注册
镜像已 load?    → 跳过 docker load
服务 active?    → 跳过 systemd restart
```
参数：`--all` / `--rpms` / `--base` / `--app` / `--data` / `--user <name>` / `--build-dir <path>`。

### 7.3 对现有脚本的增强

- `bootstrap.sh`：增加 `--offline-repo <path>` 模式，有离线仓库时不联网、直接装本地 rpm；并把 `meng` 加入 docker 组（当前盘点发现 `meng` 不在 docker 组，`docker ps` 需 sudo）。
- `make-bundle.sh`：可保留，作为 `make-offline.sh` 的子集（只打应用，不含 rpm）。
- `deploy.sh`：已支持 `--bundle`，`restore.sh` 内部最后一步直接调用 `deploy.sh --bundle` 复用其部署+健康检查逻辑。

## 8. 常见问题与排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `restore.sh` 报 OS 版本不符 | 目标机不是 openEuler 24.03 SP3 | 走在线路径重新编译，或换同版本 ISO |
| `ldd ibmcp_server` 有 not found | L2 没装全 或 ldconfig 未注册 | `restore.sh --rpms --base` 重跑；检查 `/etc/ld.so.conf.d/ibmcp-build.conf` |
| `docker load` 后镜像 digest 不符 | 离线包损坏或被篡改 | 重传，校验 sha256 |
| 服务起不来，日志缺 lib | systemd 非登录 shell 不读 `env.sh` | 依赖 ldconfig 注册（已处理），不依赖 LD_LIBRARY_PATH |
| 目标机 `dnf install` 仍想联网 | `.repo` 的 `enabled` 或 `gpgcheck` 配置 | restore.sh 写的本地 repo 设 `enabled=1`，临时 `--disablerepo=* --enablerepo=ibmbuild-local` |
| 跨机器搬 pg 卷后启动失败 | 两端 pg 小版本不一致 | 改用 `pg_dump`/`pg_restore` 逻辑迁移 |
