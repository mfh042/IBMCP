## 1. 项目定位与总体架构

### 1.1 一句话定位

IBMCP（工业黑盒集控平台）是一套面向工业现场设备的**采集 + 控制 + 监控**一体化平台：通过 Modbus TCP/RTU、MQTT、OPC UA 等协议采集设备点位，落库 PostgreSQL，提供实时监控、历史趋势、告警、远程控制，并支持 Web 与桌面客户端访问。

### 1.2 三层架构

```
┌──────────────────────────────────────────────────────────────────┐
│  客户端层                                                          │
│   ├─ Web 浏览器 ──http://<欧拉IP>/──┐   (nginx 托管的 Vue3 静态资源) │
│   └─ Tauri 桌面客户端(Windows .exe)─┘   (内嵌同一套 Vue3，走 HTTP+WS)│
└───────────────────────────────┬──────────────────────────────────┘
                                │ :80 (nginx 反代)
┌───────────────────────────────▼──────────────────────────────────┐
│  应用层（openEuler 裸机，单进程 ibmcp_server）                       │
│   C++20 + Drogon v1.9.5（HttpController / WebSocketController）    │
│   ├─ HTTP REST  :84 个端点  → 鉴权/配置/运行态/告警/控制/数据/字典/Node-RED│
│   ├─ WebSocket  :/ws/push, /api/v1/ws/collect                       │
│   ├─ 采集器(静态库) : sample_pump / orchestrator / drivers          │
│   ├─ 缓存层 Redis : 响应缓存 + Token 黑名单 + WS Pub/Sub             │
│   └─ 数据访问 : Drogon DbClient → libpq → PostgreSQL                │
└───────┬───────────────────────────────────────┬───────────────────┘
        │ :5432 (libpq)                          │ :6379 (hiredis)
┌───────▼───────────────────────────────────────▼───────────────────┐
│  基础设施层（Docker 容器，docker compose）                            │
│   ├─ PostgreSQL 15  时序/配置/运行态/字典   卷 ibmcp_pg_data         │
│   ├─ Redis 7       缓存/会话/推送骨干        卷 ibmcp_redis_data     │
│   └─ Node-RED      PLC 模拟器/协议探针(联调用) 卷 ibmcp_nodered_data │
└──────────────────────────────────────────────────────────────────┘
```

**关键设计决策**：后端 + Nginx **必须裸机跑**，不进容器——因为后端要直接链接宿主的 `libpq` 和协议驱动库（`libmodbus`/`open62541` `.so`）；只有 PG/Redis/Node-RED 三个纯服务走容器（见 [docker-compose.yml 注释](file:///E:/999-Dev/01-IBMCP-黑盒管控系统/02-IBMCP-drogon/deployments/openeuler/docker-compose.yml)）。

### 1.3 进程与端口总览（部署后）

| 进程/容器 | 形态 | 端口 | 说明 |
|-----------|------|------|------|
| `ibmcp_server` | systemd 裸机 | 8000 | Drogon 后端（含采集器），监听 0.0.0.0:8000 |
| `nginx` | systemd 裸机 | 80 | 托管前端 + 反代 `/api`、`/ws` |
| `ibmcp-postgres` | docker 容器 | 5432 | PostgreSQL 15 |
| `ibmcp-redis` | docker 容器 | 6379 | Redis 7（AOF 持久化，无密码） |
| `ibmcp-nodered` | docker 容器 | 1880 | Node-RED 联调辅助 |
| `vite`（仅开发） | Windows 本地 | 5173 | 前端 dev server，代理到 8000 |

### 4.2 采集器（backend/collector 静态库 + backend/src/collector 融合层）

| 组件 | 职责 | 依赖 |
|------|------|------|
| `orchestrator` | 启动时从 `runtime_plan_revision` 读 plan、编译、下发到 collector；配置变更时重编译 | PostgreSQL、`plan_compiler`、collector bridge |
| `plan_compiler` | 把配置表编译成采集 plan | PostgreSQL（设备/路由/点位/功能表） |
| `sample_pump` | 周期（默认 200ms，批量 500）采样点位并写库；启动暖缓存 | PostgreSQL（`using_points`）、WS Hub、collector bridge |
| `event_dispatcher` | 接收采集器事件回调 → 写设备状态表 → WS 推送 | PostgreSQL（`using_devices`/`using_device_runtime`）、WS Hub |
| `driver_factory` | 按编译宏注册可用协议 | 宏 `IBMCP_HAS_MODBUS/MQTT/OPCUA` |
| modbus_tcp/rtu 驱动 | Modbus 采集 | `libmodbus`（`<modbus/modbus.h>`） |
| mqtt 驱动 | MQTT 采集 | `libmosquitto` |
| opcua 驱动 | OPC UA 采集 | `open62541` |

> 驱动库缺失时**不阻断构建**，对应协议在运行时退化为「模拟值」（`sim_value`），见 [build.sh:102](file:///E:/999-Dev/01-IBMCP-黑盒管控系统/02-IBMCP-drogon/deployments/openeuler/build.sh) 与 [driver_factory.cpp](file:///E:/999-Dev/01-IBMCP-黑盒管控系统/02-IBMCP-drogon/backend/collector/src/drivers/driver_factory.cpp)。

### 4.3 Redis 三类用途（详见 `09`）

| 用途 | 键/频道格式 | 写入方 | 读取方 | fail-open |
|------|------------|--------|--------|-----------|
| 响应缓存 | `cache:<domain>:...` | controllers 写/失效 | `cache::getOrSet` | ✅ 未命中即回源 DB |
| Token 黑名单 | `auth:blacklist:<jti>` | 登出/刷新 (`SET ... EX`) | 鉴权 filter (`EXISTS`) | ✅ Redis 不可用时放行 |
| WS 推送骨干 | `ibmcp:ws:<topic>` (PUB/SUB) | event_dispatcher 等 `PUBLISH` | WsHub 订阅 `ibmcp:ws:*` | — |

> 关键配置：`config.json` 里 `redis_clients[].timeout = 1.0`（秒），避免 Redis 宕机时请求挂起——这是 fail-open 生效的前提。

## 8. 最终版欧拉端完整部署流程（从零到可访问）

> 目标：一台干净的 openEuler 24.03 → 浏览器访问 `http://<IP>/` 看到登录页，后端 API 健康，采集/缓存/推送全部可用。

### 8.0 先选部署形态

| 形态 | 命令 | 起哪些容器 | 适用 |
|------|------|-----------|------|
| 全量（推荐生产） | `deploy.sh --full` | PG + Redis + Node-RED | **完整功能**：缓存/黑名单/WS 推送都需要 Redis |
| 精简 | `deploy.sh`（默认 `--slim`） | 仅 PG | 仅 DB 功能；Redis 不启动 → 缓存失效但 fail-open 可运行，WS 推送不可用 |
| 离线还原 | `deploy.sh --bundle <tar.gz>` | 视 bundle | 无外网/批量交付 |

> ⚠️ 生产环境**必须用 `--full`**，否则 Redis 不起，Token 登出失效、响应缓存、实时推送三项能力全部缺失。

### 8.1 在线部署（首次，有外网）

```bash

git clone <repo> /home/meng/ibmcp     # 或 eSync 同步
cd /home/meng/ibmcp

# 1. 一键初始化环境（系统包 + 编译 Drogon/驱动 + Docker + Nginx）

# 2. 构建后端（产物 → dist/）
bash deployments/openeuler/build.sh
#    成功标志：dist/bin/ibmcp_server 存在，ldd 无 "not found"

# 3. 全量部署（起 PG+Redis+Node-RED → 跑迁移 → Nginx → systemd → 健康校验）
sudo bash deployments/openeuler/deploy.sh --full

# 4. 构建前端（在 Windows 上）并上传
#    Windows: cd frontend; npm run build  →  frontend/dist/
#    上传到欧拉后：
sudo bash deployments/openeuler/deploy.sh --frontend-dist /path/to/frontend/dist
```

`deploy.sh` 内部顺序（[deploy.sh](file:///E:/999-Dev/01-IBMCP-黑盒管控系统/02-IBMCP-drogon/deployments/openeuler/deploy.sh)）：
1. 编译（或从 bundle 还原）→ 校验 `ldd` 无缺失；
2. 起 compose 容器，等 PostgreSQL 就绪（最多 2 分钟）；
3. **幂等迁移**：仅当库为空（或 `--force-migrate`）时按序执行 `dist/migrations/*.sql`：
   `0001_initial_schema → 0002_rbac_sys_users → 0003_control_ext_command_id → 0004_drop_legacy_rbac → 0005_device_supported_ports_items`；
4. 部署前端静态文件到 `$PROJECT_ROOT/frontend-dist`；
5. 生成 Nginx 配置（替换项目根路径）→ `nginx -t` → reload；
6. 生成 systemd unit（替换 `User` 与项目根路径）→ `daemon-reload` → `enable` → `restart`；
7. 轮询 `http://127.0.0.1:8000/api/v1/ping` 做健康校验。

## 10. 运维与排障速查

| 现象 | 排查 |
|------|------|
| `ibmcp-api` 起不来 | `sudo journalctl -u ibmcp-api -n 50 --no-pager`；常见：动态库缺失（`ldd` 查，重跑 `build_drivers.sh` + `ldconfig`）、PG/Redis 未就绪、`config.json` 路径错 |
| 登录提示密码错误 | 确认装了 `libargon2`（`pkg-config --exists libargon2`）；`dist/config.json` 的 `app_secret_key` 与发 token 时一致 |
| 登出后 token 仍可用 | Redis 是否在跑（`--full`）；`auth:blacklist:*` 键是否写入：`docker exec ibmcp-redis redis-cli keys 'auth:blacklist:*'` |
| 实时数据不推送 | WS 是否经 nginx 升级（`/ws/push`、`/api/v1/ws/collect`）；Redis 频道：`redis-cli psubscribe 'ibmcp:ws:*'` 看有无消息 |
| 配置改了不生效 | 接口有缓存（`cache:config:*`），写接口会自动失效；手动清：`redis-cli --scan --pattern 'cache:*' | xargs redis-cli del` |
| 协议采集是模拟值 | `check_toolchain.sh` 看驱动库是否 MISSING；缺哪个补哪个（`build_drivers.sh`），重跑 `build.sh` |
| 请求卡住/超时 | 确认 `config.json` 的 `redis_clients[].timeout=1.0`（非 -1），否则 Redis 异常会拖挂请求 |
| 前端空白/404 | `frontend-dist/` 是否有 `index.html` 且 nginx 可读；nginx root 路径是否被 deploy.sh 正确替换 |
| 升级后端 | 改源码 → 同步到欧拉 → `bash build.sh` → `sudo systemctl restart ibmcp-api`；迁移变更需 `deploy.sh --force-migrate` |
| 升级前端 | Windows `npm run build` → 上传 → `deploy.sh --frontend-dist <dir>` 或直接替换 `frontend-dist/` → `sudo nginx -s reload` |

常用运维命令：

```bash
sudo journalctl -u ibmcp-api -f          # 后端日志实时
sudo systemctl restart ibmcp-api         # 重启后端
docker compose -f deployments/openeuler/docker-compose.yml ps   # 容器状态
docker compose -f deployments/openeuler/docker-compose.yml logs -f redis
sudo nginx -t && sudo nginx -s reload    # 校验并重载 nginx
bash deployments/openeuler/check_toolchain.sh   # 全量自检
```
